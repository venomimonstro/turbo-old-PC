# Аудит Turbo Old PC — версия 0.3.0

Дата: 27 октября 2026 года. Ветка: `main`. Аудит исходников и структуры, **без выполнения на реальной Windows**.

## Вывод

**Статус: предварительная техническая версия, НЕ production-ready.** В репозитории есть графическое приложение WPF и рабочие сценарии Windows PowerShell 5.1 для диагностики, штатной антивирусной проверки, поиска драйверов, изменений производительности с журналом. Однако нет результатов интеграционных испытаний на Windows 10/11 и проверки производительности в реальных условиях.

### Критические недостатки версии 0.2, устранённые в исходниках 0.3

1. **P0: синтаксическая склейка** окончания XAML here-string и строки PowerShell в главном окне. Разделены закрывающие маркеры; добавлены статические и PowerShell-smoke-проверки.
2. **P1: драйверы без функции выбора/установки.** Добавлены реальный поиск драйверных обновлений через Windows Update Agent (WUA), выбор одной строки в GUI и запуск загрузки/установки выбранного `UpdateID`. Установка требует UAC, новой **подтверждённой** точки восстановления и не перезагружает ПК сама.
3. **P1: отсутствие обратимости оптимизации.** Добавлены журналы «было/стало» в `%LOCALAPPDATA%\TurboOldPC\Backups`; отдельный откат последнего изменения. Область воздействия ограничена несколькими параметрами анимации текущего пользователя и планом электропитания.
4. **P1: отсутствие проверки защитных механизмов.** Добавлен read-only аудит Defender, брандмауэра, UAC, SMBv1, RDP, настроек защиты от программ-вымогателей, Windows Update.
5. **P2: нет второго уровня проверки вредоносного ПО.** В GUI есть переход к официальной автономной проверке Defender и к Microsoft Safety Scanner как дополнительной проверке. Фактическое сканирование выполняют средства Microsoft; приложение не содержит собственного движка.
6. **P2: публичная сборка отставала от исходников.** Начиная с 0.3 пакет собирается из актуального списка файлов; в проект включён локальный скрипт `tools/Build-Portable.ps1`.

### Что работает по архитектуре, но ещё НЕ подтверждено Windows-тестами

| Модуль | Предназначение | Ограничения |
|---|---|---|
| WPF UI | 9 вкладок, изолированные фоновые процессы | Не подтверждено на 100–125% масштабе, 1366×768, Win10/11 |
| Antivirus | Defender QuickScan/FullScan, переход к Offline, MSERT | Отдельного антивирусного движка и гарантии обнаружения всех угроз нет |
| Security audit | Политики и некоторые опасные конфигурации | Не сканирует все CVE и не является пентестом |
| Driver updater | Драйверы, предлагаемые текущим агентом Windows Update | **Не** скачивает автоматически OEM-драйверы с сайтов Acer, HP и др.; WUA может не предложить ничего |
| Driver safety | Требует UAC + новой точки восстановления | Точка восстановления не гарантирует восстановление работоспособности любого драйвера; Windows может отказать из-за политики или частоты |
| Turbo/UI | Анимации и задержка меню | Эффект субъективный, не прибавляет GHz/RAM |
| Turbo/Power | Схема High Performance, если доступна | Возможен рост температуры, шума и энергопотребления |
| Turbo/Rollback | Сохраняет и восстанавливает изменённые значения | Откатываются **только наши профили**. Настройки чужого ПО, обновления и удалённые файлы этим не восстанавливаются |
| Temp cleanup | Пользовательский Temp, файлы старше 48 часов, ручное согласие | Удаление необратимо. Не гарантирует ускорение |
| Installer | Установка в профиль пользователя и удаление | Нет сертификата цифровой подписи и готового нативного .exe / MSI |

### Открытые критические блокеры

- **P0 — Нет подтверждённых интеграционных тестов на Windows 10 и 11.** Обязательны запуск UI, UAC, WinDefender активный/пассивный, отсутствие интернета, отказ в доступе, HDD, ограничения восстановления системы и перезапуск.
- **P0 — Подписывание и модель доверия.** PowerShell-скрипты из архива не подписаны. Перед публичным массовым распространением нужен цифровой сертификат, публикация SHA-256 и защита от подмены исполняемого кода перед UAC. Антивирус может блокировать непроверенную доставку, это нельзя обходить отключением защиты.
- **P1 — Нет полноценного отдельного антивирусного сервиса.** Режим 24/7, собственные сигнатуры, облачная репутация файлов, поведенческий анализ, защита от шифровальщиков и песочница НЕ реализованы. Пользовательский Defender обеспечивает защиту в реальном времени, когда включён.
- **P1 — Взаимодействие с драйверами OEM.** Для индивидуального скачивания с сайтов производителя нужны проверенные каталоги, точное сопоставление HWID/OS/архитектуры, контроль подписей и политика отката; универсальный парсер сайтов OEM небезопасен.
- **P1 — Полный менеджер обновлений/CVE.** Нужны инвентаризация с версиями, надежные базы уязвимостей, корреляция продукта и CPE и управление исправлениями. Сейчас доступны конфигурационные проверки и переходы к Windows Update.
- **P1 — Нет метрик производительности до/после.** Нужны время загрузки через повторные измерения, P95 responsiveness, HDD queue, CPU idle и фиксация результата после перезагрузки.
- **P2 — UX и локализация.** Не проведены ручные сценарии доступности, экранного диктора, очень слабых машин, длинных имён устройств.
- **P2 — Нативный инсталлятор.** Сейчас portable ZIP + Install.cmd, не отдельный подписанный EXE/MSI; создание рабочего MSI требует сборки и испытаний на Windows.

## Политика безопасной оптимизации

- Нет массовой остановки служб, отключения Defender, Firewall, Windows Update, UAC или удаления драйверов ради «ускорения».
- Не устанавливаются случайные «драйвер-паки» и не исполняются скачанные произвольные EXE.
- Только изменения из заранее ограниченного списка, отдельное согласие, журнал предыдущих значений и откат. Воздействие каждого профиля объясняется в интерфейсе.
- Перед каждым драйверным обновлением требуется новая точка восстановления; если её нет, установка отменяется.
- Defender Offline запускается через интерфейс безопасности Windows, чтобы предупреждение о перезапуске и BitLocker оставалось у Microsoft.

1. Чистая Win10 x64 с Defender и без него, Win11 x64, с обычной учётной записью и администратором.

5. Измерение RAM/CPU самой утилиты, холодного/тёплого старта, нагрузки на HDD, сценариев низкой памяти.
6. Проверить итоговую сборку ZIP из `dist` и повторно выполнить дымовой тест после распаковки, собрать SHA-256.
7. Привести в порядок подпись, доверие и установку, только после этого заявлять публичный стабильный релиз.
